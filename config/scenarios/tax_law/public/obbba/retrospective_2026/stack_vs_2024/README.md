# OBBBA stacked decomposition vs. pre-OBBBA 2024 baseline (retrospective, 2026)

Scores the enacted OBBBA package as `baseline` (post-OBBBA current law) minus
`baseline_2024_pre_obbba` (pre-OBBBA / TCJA-sunset current law), decomposed into
coarse thematic provision buckets, in BL conventional order.

## Why these are REVERSION overlays (not additive)

`src/data/tax_law.R` loads the reserved `baseline/` dir as the base for **every**
scenario, then overlays that scenario's own subparameters. Because the live
`baseline` already bakes in OBBBA, an *empty* overlay = full OBBBA. So the stack
is built by **reverting** the not-yet-activated provisions back to pre-OBBBA:

- **baseline row** (runscript) → `baseline_2024_pre_obbba` = every provision reverted.
- **step `k`** → reverts provisions `k+1 … 8`; provisions `1 … k` stay at OBBBA.
- **08-estate** → reverts nothing (estate.yaml = baseline $15M, a no-op) = full OBBBA.

Consecutive differencing (baseline → 01 → 02 → … → 08) yields each bucket's
incremental contribution, and Σ = `baseline − baseline_2024_pre_obbba` = the package.

## Buckets (BL conventional order) → files reverted-through

| Step | Provision turned ON | Files/subparams (relative to prior step) |
|------|---------------------|------------------------------------------|
| 01-rates          | ordinary rate schedule | `ord.yaml` |
| 02-amt            | AMT                    | `amt.yaml` |
| 03-deductions     | std / itemized-limit / Pease / mortgage / char | `std.yaml`, `char.yaml`, `item.yaml` (non-SALT) |
| 04-salt           | SALT cap               | `item.yaml` (`salt_limit_married`, `salt_floor`, `salt_floor_thresh`) |
| 05-family         | CTC / CDCTC / PE       | `ctc.yaml`, `cdctc.yaml`, `pe.yaml` |
| 06-qbi            | QBI (§199A)            | `qbi.yaml` |
| 07-new_deductions | tips / OT / senior / auto | `below.yaml`, `agi.yaml` |
| 08-estate         | estate exemption ($7.2M→$15M) | `estate.yaml` |

Each step's dir contains the **pre-OBBBA** version of every file for provisions it
still reverts; `item.yaml` is the only file split across two buckets (deductions vs
SALT). `eitc`/`pref` differ from baseline only by off-valued machinery subparams
(zero contribution) and are intentionally not part of any bucket.
