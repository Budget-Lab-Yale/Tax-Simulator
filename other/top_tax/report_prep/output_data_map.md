## 1. Scenario naming convention

All top_tax generators live in `/nfs/roberts/project/pi_nrs36/jar335/Repositories/Tax-Simulator/other/top_tax/`:

| Script | Emits runscript | Emits tax_law dirs | Drives output vintage(s) |
|---|---|---|---|
| `levers.py` | (data module, imported by the two below) | — | — |
| `build_dial_runs.py` | `config/runscripts/top_tax/dials.csv` (+ `other/top_tax/dials_legend.csv`) | `config/scenarios/tax_law/top_tax/dials/{id}/` | `top_tax_dials_30y_v1`, `top_tax_dials_30y_v2` |
| `build_factorial.py` | `config/runscripts/top_tax/factorial.csv` (+ `other/top_tax/factorial_legend.csv`) | `config/scenarios/tax_law/top_tax/factorial/c{NNN}/` | `top_tax_v1` |
| `build_revmax_grid.py` | `config/runscripts/tests/revmax_cg.csv` | `config/scenarios/tax_law/tests/revmax/{id}/` | `kg_v3_revmax`, `revmax_eta_v1` |
| `extract_atlas_data.py` | reads factorial output → `atlas_data.json` (v1 atlas) | — | reads `top_tax_v1` |
| `fit_surrogate.py` | reads dials output → `atlas2_data.json` | — | reads `top_tax_dials_30y_v2` |

**The 8 dial levers** (`levers.py::LEVERS`), off-state = current law, increases only:

| key | label | params (off → anchors, ref) |
|---|---|---|
| `ord` | Top ordinary rate | rate: 37.0 → {39.6, 44.8, 50.0}, ref 44.8 |
| `cg` | Cap gains & qual-div top rate | rate: 20.0 → {25,30,35,40,45,50}, ref 40.0 |
| `corp` | Corporate rate | rate: 21.0 → {28.0}, ref 28.0 (single OME wedge; linear in Δτ by construction) |
| `wealth` | Annual wealth tax | rate: 0 → {0.5,1,2,3,4,5}, ref 2.0; threshold($, log): 50e6 → {50e6…1000e6}, ref 50e6 |
| `deemed` | Gains-at-death treatment | positions {off, carryover, deemed}, ref "deemed" |
| `estate` | Estate tax | rate: 40 → {40,50,60}, ref 50; exem: current-law 2027 (≈$15.39M) → {5e6, 8.46e6 (M2), 11.93e6 (M1), cur}, ref M2 |
| `qbi` | Repeal §199A | {0,1}, ref 1 |
| `taxmax` | Eliminate SS taxable max | {0,1}, ref 1 |

**ID prefixes** (`build_dial_runs.py`): `s_{key}_{slug}` solo at an anchor cell (e.g. `s_cg_r25`, `s_ord_r44p8`, `s_wealth_r1_t50`, `s_estate_r50_e8p46`, `s_qbi_on`, `s_taxmax_on`); `pr_{a}_{b}` pair at REF; `prco_{a}_deemed` lever a at REF + carryover; `t_{a}_{b}_{c}` triple at REF; `tco_{a}_{b}_deemed` two at REF + carryover; `pc_*` off-REF pair corners (e.g. `pc_cgr50_deemed`); `q01..q16` seeded holdout quiz packages (excluded from surrogate fit); `stack_ref` = **all 8 levers at REF** (the package scenario behind the dist/contribution card).

Factorial vintage `top_tax_v1` uses `c{NNN}` = zero-padded bit-mask (bit0=ord,1=cg,2=corp,3=wealth,4=deemed,5=estate,6=qbi; see `factorial_legend.csv`).

Revmax vintages: `cg_{PP:02d}pp_{regime}`, PP∈{0,5,10,15,20,25} added to the 20% top rate, regime∈{stepup, carryover, deemed}.

## 2. `top_tax_dials_30y_v2` — structure, schemas, units

**Path**: `/nfs/roberts/scratch/pi_nrs36/jar335/model_data/Tax-Simulator/v1/top_tax_dials_30y_v2/`

**Years**: sim `2027:2057` (31 years, surprise-enactment, no 2026 lead-in). `dist_years = 2027 2036`. `revenue_estimates.csv` covers 2027-2057; **the final year (2057) is always NA** (FY-lag lead-out) — drop before summing.

**198 scenario dirs** (+ baseline): 40 solo + 28 pair + 7 pairco + 56 triple + 21 tripco + 8 corner + 16 quiz + 1 stack. Identical scenario list in v1.

Per-scenario layout: `static/{detail,supplemental,totals}`, `conventional/{...}`, `conventional_no_wealth/detail` (internal wealth-bathtub pass, not a reportable leg). Baseline lacks all reform-relative supplemental files (revenue_estimates, distribution, distribution_etrs).

- **`{leg}/supplemental/revenue_estimates.csv`**: `year,total` — total = counterfactual − baseline receipts, **$B**, positive = raises revenue.
- **`static/supplemental/distribution.csv`**: 27 cols; years 2027+2036; `labor/capital/ati_baseline/net_change` in $B; `income_cutoff/agi_cutoff/net_worth_cutoff/avg*` in actual dollars; shares as fractions; `group_dimension="Income"`.
- **`static/supplemental/distribution_etrs.csv`**: 32 cols; years 2027+2036; `reform_leg` ∈ {static, conventional} = the welfare-vs-realized numerator swap; `income_definition` ∈ {agi, expanded, hs}; `ranking` ∈ {fixed, self, wealth, n/a}; `taxes_included` ∈ {death, iit, iit_pr, other, wealth_cit_vat}; `corp_convention` ∈ {capital_income, equity_supernormal, uniform_networth, n/a}; `group_dimension="Income percentile"` (also Age, Net worth, Overall, Parent status). `income_*`/`tax_*` in **$B**; `etr_*` as **fractions (0–1)**. `*_baseline` columns are baseline-fixed and identical across scenarios → use any reform scenario's file for baseline levels by group (incl. `income_cutoff` = group floor in dollars).
- **`{leg}/totals/`**: `1040.csv`, `1040_by_agi.csv`, `payroll.csv`, `estate.csv` (`year,est_tax_exp,est_returns`), `wealth.csv` (`year,wealth_tax,wealth_returns`), `receipts.csv`/`receipts_full.csv` (`revenues_payroll_tax, revenues_income_tax, outlays_tax_credits, revenues_corp_tax, revenues_estate_tax, revenues_wealth_tax, revenues_vat, revenues_other`). Dollars in $B; counts in millions.
- **`conventional/supplemental/`** extras: `kg_dynamics_summary.csv` (57 cols/yr incl. `semi_elast_implied`, `tau_B/S_avg_gw`, `carry_h_avg_gw`, `deemed_realized`), `kg_dynamics_age_profile.csv`, `kg_estate_exposure_diag_{yr}.csv`, plus serialized state .rds.
- `static/supplemental/estate_tax_detail_{2027,2036}.csv` is **per-record** (~221K rows) despite the folder.

## 3. `stack_ref` / v1 vs v2 diff — THE KEY PROVENANCE FACT

- `stack_ref` = all 8 levers at REF (`ord 44.8%, cg 40%, corp 28%, wealth 2%/$50M, deemed, estate 50%/$8.46M, qbi repeal, taxmax off`).
- **v1 and v2 configs are byte-identical** (same runscript rows, same dependency vintages: Tax-Data 2026070814, Macro 2026022522, OME 20250925). **The physics differs**: v1 run ≈ 2026-07-10; v2 run ≈ 2026-07-12 AFTER these commits: wealth-carry Tier 1.1 (`47a31b1d2`/`9bb6550ca`), estate-margins Tier 1.2 (`ef7f096dc` — kg death-value estate offset + KS own-rate code), **η re-pin 2.3992 → 2.4825** (`9b235824a`), **SIGMA_CONV 0.08 → 0.16** (`18093a990`), wealth/avoidance + hidden-ledger + entity-shifting fixes.
- So **v2 physics ≈ the methodology memo** — with ONE exception: the estate-avoidance **activation** bug (estate-lever rows don't load the avoidance module; fixed 2026-07-16 in `ff5fd8037`, AFTER v2). Estate-lever scenarios in v2 lack the KS own-rate response unless a wealth lever is also on.
- `atlas2_data.json` provenance: vintage = v2, git_sha e0bc93a1f; `date:"2026-07-10"` is a **hardcoded literal** — ignore.
- `dist_card_data.json` is pinned to **v1** (pre-new-physics) — don't mix its numbers with atlas2 numbers.

## 5. Repo-side derived data files

### `atlas2_data.json` (fit_surrogate.py over v2; 198 scenarios)
Keys: `meta`, `etr_base`, `income_levels`, `surrogate`.
- `meta`: `window=[2027,2056]`, `decades=[[2027,2036],[2037,2046],[2047,2056]]`, `gdp_fy_decades=[397363.9, 575425.3, 822024.9]` ($B cumulative FY GDP per decade), `dist_years=[2027]`, `units="$B; ETRs in percent (deltas in pp)"`.
- `meta.surrogate.quantities`: `ct/st` = conv/static decade totals (3), `cy/sy` = by-year (30), `ch/sh` = decade×head (21, decade-major), `etr/etrc` = static-numerator ("ask") vs conventional-numerator ("collected") ETR deltas (176 = 2 defs × 11 groups × 8 comps, 2027, in pp).
- `heads_order = [iit, cg, pay, corp, est, wealth, other]` (cg = CY pref-rate carve; iit = residual).
- `surrogate.solo[lever][qid]` = full knot grid (row 0 = off = zeros); `g[lever]` = per-decade dial-strength (static solo ÷ REF); `pairs["a|b"][qid]` = interaction residual at REF (kept only if > tolerance), with `byPos` for deemed-ladder pairs; `triples` same for 3-way.
- Surrogate validation: quiz n=17 max err 2.53% (median 0.50%), corners max 2.42%, by-year max 3.1%, ETR max 1.7pp; static bounds 6.5–7.5%.
- `etr_base[def][2027][group]` = baseline ETR component vectors (percent, ×100 of the CSV fractions).
- `income_levels[def][group]` = 2027 baseline income levels $B (expanded + hs).

### `eta_dial/` (η re-pin evidence)
`efull_by_eta.csv`: full-sim measured elasticity at η ∈ {2, 2.3992, 3} → E_full {−2.05, −2.44, −3.03}. `eta_repin_fit.csv`: target E_full −2.521 (= −0.6/0.238), slope 1.0155 → **η\* = 2.4825**.

### `analyze_revmax.py`
The exact 10y/30y cumulation + revmax-by-regime logic to replicate for Laffer figures. `FALLBACK_VINTAGE` is unrelated — always pass vintage explicitly.

## Gotchas

1. Baseline has no delta files (revenue_estimates/distribution/distribution_etrs) — don't glob under baseline/.
2. Trailing year of every revenue_estimates.csv is NA — drop before summing.
3. Sign: `total` = counterfactual − baseline, $B, positive = revenue gain.
4. **ETR units**: CSVs store fractions; atlas2 JSON stores percent/pp (×100). Mixing = 100× error.
5. `group_dimension` label mismatch: "Income" (distribution.csv) vs "Income percentile" (distribution_etrs.csv).
6. v1 vs v2 dials configs identical; physics differs — identify vintages by mtime/commit window, never runscript diff.
7. Every top_tax runscript in the repo NOW postdates every output vintage (2026-07-16 estate/avoidance split added `estate/avoidance` + an `estate` MTR var to all of them). No on-disk vintage reflects that fix.
8. `atlas2_data.json` provenance date is a hardcoded literal.
9. `dist_card_data.json` is pinned to v1 (one physics vintage behind atlas2).
10. `conventional_no_wealth/` = internal pass, not a revenue leg.
11. `estate_tax_detail_{yr}.csv` is per-record despite living in supplemental/.
12. Revmax vintages predate the η re-pin and Tier 1.1/1.2 builds — flag Laffer figures as pre-latest-calibration.
