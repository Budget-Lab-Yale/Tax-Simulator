Entity shifting: replace the deferral stub with tau_eq?

Code review completed July 11, 2026. “t_eq” in the question appears to refer to the repository’s tau_eq series.

Conclusion: yes, for runs that include kg_dynamics, the retained-earnings part of the C-corporation tax price should use tau_eq. It is the model’s existing expected present-value tax price for a new unrealized gain, whereas the entity-shifting module currently applies a fixed 25% reduction to every capital-gains MTR. Use tau_eq directly—not a ratio where avoidable—and retain an explicit legacy fallback for entity-only runs.

What the module does now

The Pearce–Prisinzano module sets the distribution share to alpha = 0.45 and the retained-earnings “benefit of deferral” multiplier to beta = 0.25. For either policy side it prices shareholder-level corporate income as:

tau_dist = mtr_kg_lt * [ alpha + (1 - alpha) * 0.25 ]

That price is then combined with the corporate tax rate:

tau_corp = corp.rate + (1 - corp.rate) * tau_dist

The module’s own comment says that the 25% value is a proxy and that a future version should model the behavior giving rise to it.

Why tau_eq is the appropriate replacement

tau_eq(age, year) is calculated by the capital-gains bathtub as the discounted expected tax collected per dollar that enters the unrealized-gain state at the end of that year. Its recursion includes realization, discounting, mortality, charitable transfers, heir routing/carryover, and deemed realization. It is calculated separately for baseline and policy and is written to every year’s conventional kg state file as cell_table$tau_eq_B and cell_table$tau_eq_S.

Consequently, it varies with the capital-gains tax rate, age, realization behavior, and death regime. The 25% stub cannot respond to any of these. In particular, a deemed-at-death policy makes the future tax less avoidable, so it should raise the retained-earnings tax price and reduce the incentive to select the corporate form; the current stub leaves that channel unchanged.

Recommended formula

Keep the existing 45% current-distribution assumption, but price the two pieces separately:

tau_dist_S(i) = alpha * mtr_kg_lt_S(i) + (1 - alpha) * tau_eq_S(age_i, year)
tau_dist_B(i) = alpha * mtr_kg_lt_B(i) + (1 - alpha) * tau_eq_B(age_i, year)

tau_corp_j(i) = corp.rate_j + (1 - corp.rate_j) * tau_dist_j(i)   # j = B, S

This is algebraically the same as replacing 0.25 with tau_eq / mtr_kg_lt only when the denominator is nonzero and both objects use the same gain-tax rate. The direct form is better: it avoids division by zero and states the economics clearly. It also allows tau_eq to be a cell-level expected tax price while the paid-distribution leg remains the record’s calculator-measured MTR.

Magnitude check

As a rough diagnostic, the archived current-law validation series (not a calibration target) has a gain-stock-weighted tau_eq of 6.48% versus a gain-stock-weighted statutory gain MTR of 20.14%: an implied ratio of 0.322. At ages 40, 60, and 80 the displayed ratios are approximately 0.45, 0.34, and 0.26, respectively. Thus the live 0.25 stub is not merely a uniform approximation; it misses meaningful age and policy variation.

Safe integration design

  1. Only enable the dynamic price when kg_dynamics/ is present. Read that year’s existing kg state file and join the two tau_eq columns to records by age_cohort.
  2. Require finite, nonnegative values for both sides. The kg module already attaches age_cohort before entity shifting in the pinned order kg_dynamics → conversion → entity_shifting → evasion.
  3. For entity-only scenarios, preserve the documented beta = 0.25 legacy approximation (or make the fallback a named scenario parameter). Do not silently substitute zero.
  4. Test: baseline/no-law-change is a no-op; a CG-rate change moves the retained leg through tau_eq; deemed, carryover, and step-up produce the expected ordering; legacy entity-only runs remain reproducible.
  5. Re-residualize the sigma conversion parameter after this change. Entity shifting is one component of the combined top-end behavioral response, so changing its tax price changes the remaining conversion margin.
Important scope limitation. tau_eq prices a dollar that behaves like the model’s aggregate unrealized-gain pool. The entity module would therefore be assuming that retained C-corporate earnings have the same realization, mortality, charitable-transfer, and death-regime path as that pool. This is a substantial improvement over a universal 25% discount, but it is still a reduced-form proxy—not a dedicated corporate retained-earnings lifecycle model. The module also continues to proxy dividend taxation with mtr_kg_lt, which should be revisited separately if policies create a dividend/gain rate differential.
