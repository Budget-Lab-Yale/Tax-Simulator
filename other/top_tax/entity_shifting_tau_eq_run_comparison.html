Entity Shifting: tau_eq vs. legacy retained-share deferral

This report summarizes the implementation change and the clean one-year Slurm A/B test. The clean runs used separate output vintages so the job chains did not collide.

What changed

The Pearce-Prisinzano entity-shifting module now uses tau_eq directly as the deferral price signal whenever the run is paired with kg_dynamics. The legacy path still uses the fixed retained-share shortcut for comparison runs.

Interpretation

  • The kg dynamics summary was unchanged between the two runs, which is consistent with the change being in the deferral wedge calculation rather than the mechanical state evolution.
  • The 1040 totals move mainly in the affected activity categories, with the largest shifts in counts of taxable kg, partnership active, S-corp, and Sch. E filers.
  • The tau_eq specification produces a higher 2026 revenue estimate than the legacy shortcut in this policy configuration.
  • The clean A/B test is the only result set that should be treated as valid; the earlier retry chains were discarded because they reused colliding output staging.
